## Цель

Что должно получиться — 2–4 предложения, с точки зрения пользователя и кода.

## Вне задачи

Что сознательно не делается (чтобы исполнитель не расширял объём).

## Правила, которые прочитать

Только нужные для этой задачи (а не всю `.claude/rules/`): например, `code.md`, `core.md`,
`db.md`, `api.md`, `svelte.md`, `components.md`, `ui.md`, `tests.md`, `e2e.md`, `bot.md`,
`worker.md`. Плюс скилл-источник, если задача по нему: `.claude/skills/add-new-module/SKILL.md`
(разделы 3–4, шаблоны `templates/`), `.claude/skills/cover-module/SKILL.md`.

## Решения

Принятые решения и почему — то, что исполнитель не должен пересматривать: модель данных
(поля, типы, ограничения, индексы), сигнатуры сервиса и ошибки, эндпоинты, `TestId`, тексты
в константах, выбранные готовые части проекта, имена.

## Тесты

Какие тесты написать и что каждый проверяет (unit, integration, e2e — по правилам).
Запускает их не исполнитель, а `verifier` (через основного агента).

## Готово, когда

- все файлы из таблицы сделаны, `bun run format` прошёл;
- `bun run lint` и `bun run check` без ошибок;
- <критерии задачи>.

## Если неясно

Исполнитель останавливается и возвращает вопрос, а не выбирает сам, если: решения нет в спеке
и его нельзя однозначно вывести из правил; спек противоречит правилам или коду; задача
требует изменить файл вне таблицы, кроме очевидных мелочей (импорт, экспорт в `index.ts`).
