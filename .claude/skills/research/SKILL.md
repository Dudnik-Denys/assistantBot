# research

Проведи аудит: `$ARGUMENTS`

Протокол исследователей (порядок работы, ограничения, поля находки, формат отчёта) — `.claude/rules/research.md`. Этот скилл только выбирает области, запускает агентов и сводит их отчёты.

## 1. Области

| Область | Агент | Что смотрит |
|---|---|---|
| `rules` | `research-rules` | CLAUDE.md, `rules/`, `knownIssue.md`, `settings.json`, README: соответствие коду, противоречия, дублирование, устаревшее |
| `skills` | `research-skills` | скиллы (с шаблонами), команды, агенты: соответствие правилам и коду, рабочие ли шаги и пути |
| `tests` | `research-tests` | unit и integration, полнота покрытия |
| `e2e` | `research-e2e` | e2e-тесты Playwright и готовность модулей без них |
| `db` | `research-db` | Prisma, миграции, SQL, тестовая БД |
| `schemas` | `research-schemas` | zod-схемы, константы, типы, env во всех пакетах |
| `core` | `research-core` | сервисы, ошибки, публичный API `packages/core` |
| `bot` | `research-bot` | `apps/bot` |
| `worker` | `research-worker` | `apps/worker`: очереди, задачи, планировщик, отправка в Telegram |
| `ui` | `research-ui` | `lib/components`, `app.css` |
| `api` | `research-api` | `routes/api`, `lib/server`, хуки, HTTP-клиент |
| `web` | `research-web` | страницы, `lib/reactive`, Telegram, утилиты, конфиг SvelteKit |
| `tooling` | `research-tooling` | `run.sh`, `deploy/`, `package.json`, Biome/Prettier, tsconfig, CI, compose, `.gitignore`, настройки редактора |

`docs` — группа, а не отдельный агент: запускает `rules` и `skills` (два агента).

Тяжесть — примерный расход одного агента (сколько кода он читает): **тяжёлые** — `tests`, `schemas`, `web`; **средние** — `rules`, `skills`, `ui`, `api`, `core`, `tooling`; **лёгкие** — `db`, `bot`, `worker`; `e2e` — между лёгкими и средними (растёт с каждым покрытым модулем). Подписка пользователя — Pro с небольшим 5-часовым лимитом: полный прогон занимает большую его часть, поэтому агенты не запускаются «на всякий случай».

Разбор аргументов:

- **Нет аргументов** (или только `deep`) — ничего не запускай. Покажи таблицу областей с тяжестью, предложи `changed` (если есть изменения — сколько файлов и каких областей) и спроси, что запустить.
- `all` — все тринадцать (с подтверждением, см. ниже).
- `docs` — то же, что `rules skills`.
- Перечислены области — только они. Неизвестное слово → покажи таблицу и попроси выбрать; сам не угадывай.
- `deep` — глубокий аудит: агенты запускаются с `effort: xhigh` вместо `high` из их файлов. Для аудита перед выпуском, после большого рефакторинга и для одной-двух областей, где пропуск дорог (`core`, `api`, `db`, `worker`). Сочетается с остальными аргументами (`/research core api deep`).
- `changed` — только изменённые файлы: `git status --porcelain` и `git diff --name-only origin/main...HEAD`. Каждому агенту передай список тех, что попадают в его область (по разделу «Область» в его файле); агенту без изменённых файлов задание не давай. Если изменений нет — скажи об этом и остановись.

**Подтверждение расхода.** Если получилось больше трёх агентов (в том числе `all` и `changed`, задевший много областей) — до запуска перечисли выбранные области с их тяжестью, предупреди, что прогон заметно расходует лимит Pro, и предложи сузить (только тяжёлые изменения, часть областей сейчас, остальные — в другом окне). Запускай после явного «да». Три агента и меньше — без вопроса. С `deep` порог ниже: подтверждение — уже при двух агентах и больше (xhigh заметно дороже на агента).

## 2. Запуск

Все выбранные агенты — **одним сообщением, параллельно** (инструмент Agent, `subagent_type: research-<область>`). Задание каждому — коротко:

- режим: «вся область» или «только эти файлы: …»;
- напоминание: протокол — `.claude/rules/research.md`, ничего не менять, каждую находку перепроверить.

Модель не переопределяй: у агентов `sonnet`, аудит требует суждения. Уровень усилий — из файлов агентов (`high`); только при `deep` передай при запуске `effort: xhigh`. Дождись отчётов всех агентов (уведомления о завершении) и не пересказывай их до этого.

## 3. Сводка

1. **Собери** находки всех агентов. Одинаковые (`путь:строка` и суть) объедини, указав обе области.
2. **«За пределами области»**: если замечание уже есть у агента-владельца — отбрось; если нет — перенеси в находки с пометкой, кто заметил.
3. **Перепроверь сам** все находки высокой серьёзности и все, что выглядят сомнительно: открой `путь:строка`, сверь с правилом. Не подтвердилось — убери и упомяни в конце одной строкой («отклонено: …, причина»).
4. Не исправляй ничего — ни код, ни правила.

## 4. Отчёт пользователю

По-русски, номера сквозные — чтобы пользователь мог ответить «1 — правь, 4 — оставь»:

1. Итог: сколько областей и файлов просмотрено, сколько находок по серьёзности. Таблица «область — высоких / средних / низких».
2. **Находки** — сгруппированы по серьёзности (высокая → низкая), внутри — по области. Для каждой: номер, `путь:строка`, что не так, правило (файл → раздел), предложение.
3. **Правила и документация устарели** — находки типа «устарело» отдельным блоком: они правятся в `.claude/`, а не в коде.
4. **Вопросы** — что решает пользователь, с вариантами и твоей рекомендацией.
5. В конце — что предлагаешь сделать первым (группы правок, которые разумно сделать одним заходом).

Если находок нет — короткий итог и таблица областей.

После ответа пользователя исправления делаются обычной работой, проверка — через `verifier`.
