# get-deep-info

Разбери файл: `$ARGUMENTS`

## 1. Проверь аргумент

Нужен точный путь к одному файлу с расширением, от корня репозитория.

- **Аргумента нет** → ничего не разбирай. Ответь, что нужен путь к файлу, и приведи пример: `/get-deep-info apps/bot/src/index.ts`. Для обзора папки или проекта предложи `/get-info`.
- **Указана папка** → не разбирай. Предложи `/get-info <папка>` или попроси выбрать файл; перечисли файлы папки.
- **Файл не найден** → найди похожие через Glob (`**/<имя>*`) и предложи их. Сам не выбирай, даже если совпадение одно.
- **Секрет** (`.env`, `.env.*` кроме `.env.example`, `*.pem`, `*.key`, `*.secrets`) → не открывай. Скажи, что файл содержит секреты и разбор недоступен.
- **Сгенерированный файл или зависимость** (`node_modules/`, `.svelte-kit/`, `packages/db/src/generated/`, `build/`, lock-файлы) → предупреди, что это не исходный код проекта, и разбирай, только если пользователь подтвердит.

## 2. Подготовка

1. Прочитай файл целиком.
2. Найди, что он импортирует из проекта, и загляни туда, насколько нужно, чтобы понять используемые функции и типы.
3. Найди через Grep, кто использует этот файл. Это нужно для раздела «Место в проекте».

## 3. Разбор

Разбей файл на смысловые блоки в порядке их следования: импорты, константы и конфигурация, типы, каждая функция или класс, middleware, обработчики, разметка и т. п. Мелкие однотипные строки объединяй в один блок, большие функции дели на шаги.

Для каждого блока:

```
### <номер>. <название блока> (`<файл>:<строки начала>–<конца>`)

<код блока или его ключевой фрагмент; блоки длиннее ~30 строк — сокращённо, с `// …`>

**Что делает:** пошагово, что происходит при выполнении.
**Зачем:** какую задачу решает и почему сделано именно так (если причина видна из кода, комментариев или CLAUDE.md).
**Детали:** неочевидные моменты — побочные эффекты, асинхронность, обработка ошибок, граничные случаи, особенности используемых API и библиотек. Пропусти, если нечего сказать.
```

Ответ целиком:

```
## <путь>

**Кратко:** 2–3 предложения о назначении файла.

**Место в проекте:** кто использует файл, что использует он; как и когда он выполняется (процесс, маршрут, момент вызова).

## Разбор по блокам
<блоки>

## Как это работает вместе
Поток выполнения от точки входа до результата, через блоки по номерам.

## На что обратить внимание
Возможные проблемы, хрупкие места, расхождения с правилами проекта (CLAUDE.md, `.claude/rules/`). Пропусти, если ничего нет.
```

## 4. Общие правила

- Отвечай на русском, имена из кода — в `код`.
- Объясняй то, что делает код, а не то, что он, вероятно, должен делать. Если поведение зависит от библиотеки и ты не уверен в деталях, скажи об этом.
- Ничего не меняй в файле: это только разбор.
