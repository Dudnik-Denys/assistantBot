# get-deep-info

Разбери: `$ARGUMENTS`

## 1. Проверь аргумент

Пути — от корня репозитория; ведущий `./` и завершающий `/` не важны.

- **Аргумента нет** → ничего не разбирай. Покажи, как вызывать: `/get-deep-info apps/bot/src/index.ts`, `/get-deep-info apps/bot/src`, `/get-deep-info project`. Для краткого обзора предложи `/get-info`.
- **Файл** → режим «файл».
- **Папка** → режим «папка».
- **`project`** → режим «проект».
- **Ничего не найдено** → найди похожие через Glob (`**/<имя>*`) и предложи их. Сам не выбирай, даже если совпадение одно.

Не разбирай:

- **Секреты** (`.env`, `.env.*` кроме `.env.example`, `*.pem`, `*.key`, `*.secrets`) — не открывай; скажи, что файл есть и что он содержит секреты.
- **Сгенерированное и зависимости** (`node_modules/`, `.svelte-kit/`, `packages/db/src/generated/`, `build/`, lock-файлы) — это не исходный код проекта. Указан такой файл напрямую — предупреди и разбирай, только если пользователь подтвердит; внутри папки — пропускай молча.

Список файлов папки — `git ls-files --cached --others --exclude-standard <папка>`: он сам пропускает то, что в `.gitignore`.

## 2. Объём (папка и проект)

Разбор по блокам — дорогой: на подписке Pro большой разбор заметно расходует 5-часовой лимит. До начала посчитай объём: число файлов и строк (`wc -l` по списку файлов).

- **До ~15 файлов и ~1 500 строк** — разбирай сразу.
- **Больше** — не начинай: покажи число файлов и строк по вложенным папкам и предложи варианты — разобрать всё, только часть папок, или сначала `/get-info` для обзора. Начинай после ответа.
- **`project`** — всегда по частям: план по верхнеуровневым папкам (`apps/web`, `apps/bot`, `packages/core`, `packages/db`, `tests`, `.claude`, корневые файлы) с объёмом каждой; после подтверждения — одна часть за ответ, в конце части — предложение перейти к следующей.

## 3. Разбор файла

Подготовка:

1. Прочитай файл целиком.
2. Найди, что он импортирует из проекта, и загляни туда, насколько нужно, чтобы понять используемые функции и типы.
3. Найди через Grep, кто использует этот файл, — для раздела «Место в проекте».

Разбей файл на смысловые блоки в порядке их следования: импорты, константы и конфигурация, типы, каждая функция или класс, middleware, обработчики, разметка и т. п. Мелкие однотипные строки объединяй в один блок, большие функции дели на шаги.

Для каждого блока:

```
### <номер>. <название блока> (`<файл>:<строки начала>–<конца>`)

<код блока или его ключевой фрагмент; блоки длиннее ~30 строк — сокращённо, с `// …`>

**Что делает:** пошагово, что происходит при выполнении.
**Зачем:** какую задачу решает и почему сделано именно так (если причина видна из кода, комментариев или CLAUDE.md).
**Детали:** неочевидные моменты — побочные эффекты, асинхронность, обработка ошибок, граничные случаи, особенности используемых API и библиотек. Пропусти, если нечего сказать.
```

Ответ для режима «файл»:

```
## <путь>

**Кратко:** 2–3 предложения о назначении файла.

**Место в проекте:** кто использует файл, что использует он; как и когда он выполняется (процесс, маршрут, момент вызова).

## Разбор по блокам
<блоки>

## Как это работает вместе
Поток выполнения от точки входа до результата, через блоки по номерам.

## На что обратить внимание
Возможные проблемы, хрупкие места, расхождения с правилами проекта (CLAUDE.md, `.claude/rules/`). Пропусти, если ничего нет.
```

## 4. Разбор папки

Все файлы папки **и всех вложенных папок**, рекурсивно. Порядок: сначала файлы самой папки, затем вложенные папки по одной; внутри — от главного к вспомогательному (точки входа, маршруты, сервисы раньше утилит, типов и конфигов).

Каждый файл — по разделу 3, но компактнее: без раздела «Место в проекте» у каждого файла (связи — в общем разделе папки), а простые файлы (константы, типы, реэкспорты, короткие конфиги до ~20 строк) — одним блоком без деления. Код в блоках — только ключевые фрагменты.

```
## <папка>/

**Кратко:** роль папки в проекте, как устроена внутри.

**Состав:** дерево вложенных папок и файлов с числом строк.

## <папка>/<файл>
<блоки>

## <папка>/<вложенная>/
Одно-два предложения о роли вложенной папки, затем её файлы так же.

## Как это работает вместе
Потоки данных и вызовов между файлами и вложенными папками; точки входа; что папка берёт снаружи и что отдаёт.

## На что обратить внимание
Проблемы, дублирование между файлами, расхождения с правилами. Пропусти, если ничего нет.
```

## 5. Разбор проекта

1. Прочитай `.claude/CLAUDE.md` и правила в `.claude/rules/` — источник о целях, стеке и архитектуре.
2. Составь план по частям (раздел 2) и дождись подтверждения.
3. Каждую часть разбирай как папку (раздел 4). Первым ответом, до первой части, — короткая карта проекта: части, их роли и путь запроса от Telegram (бот / Mini App) до БД и обратно, со ссылками на части, где это будет разобрано.
4. После последней части — раздел «Как всё связано»: сквозные потоки между частями (авторизация, запрос заметок, команда бота) и общие места, которые используют несколько частей.

## 6. Общие правила

- Отвечай на русском, имена из кода — в `код`; ссылки на места — `путь:строка`.
- Объясняй то, что делает код, а не то, что он, вероятно, должен делать. Если поведение зависит от библиотеки и ты не уверен в деталях, скажи об этом.
- Ничего не меняй: это только разбор.
