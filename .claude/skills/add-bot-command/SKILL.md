# add-bot-command

Добавь в бота: `$ARGUMENTS`

Правила — `.claude/rules/bot.md` (раздел «Как добавить команду или раздел» — порядок, остальные — как писать), общие — `code.md`, тесты — `tests.md`. Прочитай `bot.md` целиком перед началом.

## 1. Уточни задачу

- Нет аргумента — попроси имя команды и что она делает; покажи существующие (`apps/bot/src/constants/commands.ts`).
- **Команда или раздел?** Одна команда с одним ответом — `routers/commands/<команда>.ts`. Несколько команд и кнопок одной функции (счётчики: список, `+1`, сброс) — `routers/<раздел>.ts`.
- **Кому доступна?** По умолчанию — только своим (`createPrivateRouter`). В `publicRouter` — только если нужна до входа (как `/id`); спроси, если неочевидно.
- **Видна в меню?** Пользовательская — да (`COMMAND_MENU`, описание по-русски); служебная — нет.
- **Логика** — уже есть сервис в core (как у Mini App)? Бот вызывает его, а не пишет свою. Нет — сначала логика в core (`core.md`); если это новый модуль целиком — `/add-new-module`.

Покажи план (файлы, команда, место в цепочке) и дождись подтверждения, если появляется новый раздел или новая зависимость.

## 2. Код

По шагам `bot.md`:

1. Имя — в `BotCommand`; видимую — в `COMMAND_MENU`.
2. Роутер: без зависимостей — готовый `Composer`; с сервисами или настройками — фабрика `createXRouter(deps)`, тип зависимостей — `Pick<RouterDeps, …>`.
3. Новый сервис — в `RouterDeps` и `BotDeps`, создать в `index.ts`, передать в `createBot`.
4. Подключить в `createPrivateRouter` (или `publicRouter`).
5. Кнопки: клавиатура — `keyboards/<раздел>.ts` (данные аргументами); префикс данных — константа в `constants/` (`counter:inc:<id>`, ≤ 64 байт); разбор `callback_data` — схемой в `apps/bot/src/schemas/`; обработчик — `callbackQuery` по префиксу и всегда `answerCallbackQuery()`.
6. Ввод пользователя — схемой до сервиса; ответы с разметкой — `parse_mode: 'HTML'` и экранирование пользовательских строк; `NotFoundError` и подобные — понятным ответом, остальные ошибки — в `bot.catch`.

## 3. Тест

Integration-тест в `tests/integration/<модуль>/` по образцу `allowlist.test.ts`: контекст grammY — простой объект с нужными полями, сервисы — настоящие на тестовой БД. Проверить: ответ на успешный путь, чужие данные, неверный ввод, разбор данных кнопок. Схема данных кнопок — unit-тест.

## 4. Проверка и отчёт

`bun run format`, `verifier` в режиме `server`. Бота сам не запускай для проверки (он читает `.env`) — дай пользователю список ручных проверок в Telegram (`/dev-start`): команда в меню, ответ, кнопки, ошибки, доступ незнакомому пользователю. Если команда меняет меню — напомни, что меню обновится при следующем запуске бота (`setMyCommands`).
