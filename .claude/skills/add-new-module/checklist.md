# Чек-лист нового модуля

Пункты «если есть» — только для того, что вошло в план модуля.

## БД и core

Соглашения по моделям, миграциям и SQL — `.claude/rules/db.md`.

- [ ] Модель: `id` `uuid(7)`, `userId` со связью `onDelete: Cascade`, `createdAt`/`updatedAt` в `Timestamptz(3)`, индекс `[userId, …]` под основной список.
- [ ] Обратная связь в модели `User`.
- [ ] Миграция создана и применена; ручной SQL помечен `-- Изменено вручную: …`, generated-выражения повторены в `dbgenerated(...)` так, чтобы `migrate diff` был пустым.
- [ ] Значения по умолчанию со смыслом — константы в core, а не `@default` в схеме.
- [ ] zod-схема ввода — в `packages/core/src/schemas/<модуль>/`, рядом только выведенный тип: `trim`, лимиты из констант, сообщения на русском (и для отсутствующего поля — `z.string({ error })`).
- [ ] Константы модуля — в `packages/core/src/constants/<модуль>.ts` без зависимостей; нужные клиенту — через вход `./constants/<модуль>`.
- [ ] DTO — схемой в `packages/core/src/schemas/<модуль>/<сущность>-dto.ts` (поверх `RecordDtoSchema`), тип выведен из неё и реэкспортирован из `<модуль>/types.ts`; схема — во входе `@tgab/core/dto`; даты — ISO-строки, `bigint` — строки.
- [ ] Каждый метод сервиса принимает `userId` и фильтрует по нему; чужой или несуществующий id → `NotFoundError` (не 403).
- [ ] Формат id — общим `assertId`; текст «не найдено» — одна константа `NOT_FOUND`.
- [ ] Запрос списка — общий `ListQuerySchema`; порядок — `updatedAt desc` (на нём держится кеш `RestResource`) или `createdAt desc` с `{ stableOrder: true }` у ресурса (как у счётчиков).
- [ ] Ввод снаружи — `unknown`, разбирается в сервисе через `parseInput(Схема, input)` (ошибка — `ValidationError` → 400, а не `ZodError` → 500); у вызывающих нет `as`.
- [ ] Текст «не найдено» — константа `<СУЩНОСТЬ>_NOT_FOUND_MESSAGE` в `constants/<модуль>.ts`; `toXDto` не экспортируется.
- [ ] В `packages/core/src/index.ts` — именованные экспорты только используемого приложениями.

## API и клиент
- [ ] Сервис зарегистрирован в `lib/server/services.ts`.
- [ ] Эндпоинты тонкие: `requireUser` → сервис → `Response.json`, всё в `handleApi`; `201` на создание, `204` на удаление; лишних методов нет.
- [ ] Ресурс в `lib/api.ts` через `RestResource` (или `ReadResource`, если записи создаёт сервер); доп. действия — наследником; действие, меняющее запись, обновляет кеш списка (`cacheItem`).
