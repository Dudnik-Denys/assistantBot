# update-deps

Обнови зависимости: `$ARGUMENTS`

Это работа с решениями по ходу (что ломается, как переписать код), поэтому скилл, а не команда. Только посмотреть устаревшее — `/outdated`.

## 1. Что обновлять

1. `bun outdated --filter="*"` — текущие и последние версии во всех пакетах.
2. По аргументу: пакет или группа — только они; `patch` / `minor` — все обновления не выше этого уровня; без аргумента — покажи таблицу (пакет — текущая — последняя — уровень) и предложи порядок: сначала patch и minor одной партией, затем каждая мажорная группа отдельно. Дождись выбора.
3. **Группы** обновляются только вместе, до одной версии во всех `package.json`:
   - `svelte`, `@sveltejs/kit`, `@sveltejs/vite-plugin-svelte`, `@sveltejs/adapter-node`, `svelte-check`, `vite`;
   - `prisma`, `@prisma/client`, `@prisma/adapter-pg`;
   - `tailwindcss`, `@tailwindcss/vite`, `prettier-plugin-tailwindcss`;
   - `@biomejs/biome`, `prettier` и плагины Prettier;
   - `typescript`, `@types/bun`, `@types/node`; версия Bun в `.github/workflows/ci.yml` — вместе с `@types/bun`.

## 2. Мажорные обновления — до установки

Для каждой мажорной версии найди changelog / migration guide (официальный сайт или GitHub releases пакета) и выпиши, что касается проекта: удалённые и устаревшие API, которые используются в коде (`git grep`), смену конфигурации, требования к версиям Node/Bun. Покажи пользователю: что поменяется в коде и правилах, риск, рекомендация (обновлять сейчас или отложить). Ставь после подтверждения.

## 3. Обновление

1. Обнови версии в `package.json` (тот же диапазон, что был: `^` остаётся `^`) и выполни `bun install`. Prisma после обновления — `bun run db:generate`.
2. Исправь код под новый API **по правилам проекта**, а не обходом. Устаревшие (`@deprecated`) вызовы — заменить сразу, если замена есть.
3. Изменились рекомендации библиотеки, на которые опираются правила (`.claude/rules/svelte.md` — «Если правило расходится с документацией актуальной версии — верна документация»), — обнови правила и примеры в них.
4. Шаблоны скилла `add-new-module` — тоже под новый API, если затронуты.

## 4. Проверка

`bun run format`, затем `verifier` в режиме `all`. Для мажорных обновлений web — ещё и ручная проверка в браузере и Telegram (`/dev-start`): главные экраны, свайп, автосохранение. Для Prisma — `/migration`, если генератор требует новой миграции (обычно нет; `prisma migrate diff` по схеме против миграций должен быть пустым).

## 5. Отчёт

Таблица «пакет — было — стало», что пришлось поменять в коде и правилах, результат проверок, что проверить вручную. Коммит — одной группой на коммит (`/commit-plan`): так обновление легко откатить.
