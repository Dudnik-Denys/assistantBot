# add-worker-job

Добавь фоновую задачу: `$ARGUMENTS`

Источник принципов — `.claude/CLAUDE.md` («Architecture»: воркер — отдельный процесс; напоминания — данные в Postgres с `nextRunAt`, а не cron на каждое; периодическая задача раз в минуту выбирает наступившее через `SKIP LOCKED`; Redis — `noeviction` и AOF; лимиты Telegram — лимитер очереди и `@grammyjs/auto-retry`). Общие правила — `code.md`, `core.md`, `db.md`, `tests.md`. Перед началом проверь по официальной документации BullMQ актуальный API (`Queue`, `Worker`, `upsertJobScheduler` для повторяющихся задач, `limiter`) — не по памяти.

## 1. Где что лежит

Воркер уже есть: устройство и правила задач — `.claude/rules/worker.md`, живые образцы — `apps/worker/src/jobs/counters-due.ts` (периодическая выборка через сервис core) и `jobs/counter-notification.ts` (отправка в Telegram). Новая задача повторяет их устройство: имена очереди и задачи — в `constants/queues.ts`, очередь — в `queues/index.ts`, обработчик-фабрика — в `jobs/`, повторяющаяся — в `schedulers.ts`, `Worker` — в `index.ts`.

## 2. Задача

Правила задачи (данные в Postgres, выборка `SKIP LOCKED`, идемпотентный `jobId`, лимиты Telegram, повторы и ошибки) — `worker.md`, «Правила задач». Здесь только порядок работы:

1. **Данные и логика — в core.** Что и когда выполнить — поля модели (`nextRunAt`, статус, `userId`); выбор наступившего и сдвиг (правило повтора в часовом поясе пользователя, хранение в UTC) — метод сервиса core.
2. **Обработчик** — тонкий, над методом сервиса; данные задачи — схема в `schemas/`.
3. **Отправка в Telegram** — через `Api` из `index.ts`; тексты — `messages/`, клавиатуры — `keyboards/`.
4. **Документация**: новая очередь или правило — в `worker.md`.

## 3. Тесты и проверка

Integration: сервис выборки и сдвига на тестовой БД (наступившие/будущие, чужие пользователи, часовые пояса и переход на летнее время — unit для вычисления). Обработчик — с подменённой отправкой в Telegram (функция-зависимость), без настоящего Redis, если логика от него не зависит. `bun run format`, `verifier` (`server`). Ручная проверка — `/dev-start` и созданная запись с ближайшим временем.
