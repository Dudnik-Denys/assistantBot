# refactoring-design

Отрефакторить: `$ARGUMENTS`

Роли (CLAUDE.md, «Распределение работы»): как переделать — решает основной агент (Opus) в этом скилле, правки по спеку пишет `implementer` (Sonnet), проверяет `verifier`. `effort: xhigh` действует на ход запуска скилла — на нём разбор и черновик решения.

## 1. Исходные данные

- Отчёт `/research` из этого диалога (номера находок — из аргумента; без номеров — все находки, которые пользователь согласился править) или описание задачи. Нет ни того, ни другого — спроси, что рефакторить; аудит не запускай сам.
- Перепроверь каждую находку по коду (`путь:строка`) и правилу: устаревшую или ложную — убери из работы и скажи об этом.
- Прочитай правила затронутых областей и **весь код, которого коснётся правка**, включая места использования (`git grep` по именам) — рефакторинг ломает вызывающих.

## 2. Решение

Сгруппируй находки по смыслу (одна общая часть, один слой, одна область). Для каждой группы покажи пользователю:

- что не так сейчас (кратко, со ссылкой на находки);
- целевое устройство: что выносится или переносится, куда (файл), новое API (имена, сигнатуры), что удаляется;
- какие файлы меняются, включая вызывающих;
- риски: что может сломаться, чем это поймают тесты; нужно ли сначала добавить тесты на текущее поведение;
- правила, которые нужно обновить вместе с кодом (`.claude/rules/`, CLAUDE.md, скиллы) — правила и код не должны расходиться.

Порядок групп — от независимых и мелких к крупным; группы с непересекающимися файлами можно отдавать исполнителям параллельно (проверки всё равно по очереди — общая тестовая БД). Спорное — варианты с рекомендацией.

**Жди подтверждения** («1 — делай, 3 — иначе, 4 — не надо»).

## 3. Спеки

На каждую группу (или несколько мелких вместе) — `.claude/templates/spec.md` во временную папку сессии (scratchpad). Решения, новые сигнатуры, полный список файлов с вызывающими, правила для чтения, обновление правил.

## 4. Исполнение и проверка

1. `implementer` на группу (путь к спеку); независимые группы — можно параллельно.
2. Остановка с вопросом — ответь, если следует из согласованного, иначе спроси пользователя; продолжи исполнителя (`SendMessage`).
3. Ревью диффа по спеку и правилам; мелочи — сам, существенное — исполнителю.
4. `verifier` по CLAUDE.md, «Commands»: тесты затронутых модулей (Haiku, по очереди), затем `ui` / `server` / `all` (Sonnet). Падения — по `/fix-bug` (`bug-fixer`).
5. Правки в `.claude/` (правила, скиллы) — сам: они короткие и требуют контекста решения.

## 5. Отчёт

По группам: что изменено, файлы, результаты проверок, обновлённые правила, отклонённые находки (почему). Не коммить.
