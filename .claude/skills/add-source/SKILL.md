# add-source

Добавь источник: `$ARGUMENTS`

Принципы — `.claude/CLAUDE.md`: погода — отдельный сервис на Python (FastAPI, пакеты через uv), схему БД он не меняет (данные по HTTP или только чтение своих таблиц); вакансии — источники с официальным API или RSS предпочтительнее парсинга HTML (хрупкий, IP дата-центров блокируют). `code.md` — паттерны: стратегия для источников, адаптер для внешних API, паттерн назван в коде.

## 1. Проверь аргумент и источник

- Тип — `weather` или `vacancies`; иначе спроси.
- По документации источника (официальной): тип доступа (API, RSS, HTML), авторизация (ключ → переменная окружения, в README и схему env, секрет — не в код), лимиты запросов, условия использования (разрешено ли автоматическое получение), формат ответа. HTML-парсинг или запрет в условиях — предупреди и дождись решения.
- Первый источник своего типа — сначала каркас (шаг 2), после подтверждения.

## 2. Каркас (первый источник)

- **weather** (`apps/weather`, если нет): проект uv (`pyproject.toml`), FastAPI-приложение, модуль `sources/` с интерфейсом источника (протокол / абстрактный класс: получить прогноз на место и период → общая модель прогноза, pydantic), реестр источников, эндпоинт для TS-стороны, тесты `pytest`. Правило `.claude/rules/weather.md` (структура, стиль Python, как добавить источник), строки в `CLAUDE.md` и README, запуск в `run.sh`/`dev` (через `uv run`), агент `research-weather` и область в `/research`.
- **vacancies** (модуль в core): интерфейс источника в `packages/core/src/vacancies/sources/` (получить вакансии по запросу → общий DTO), реестр, сервис выборки и дедупликации. Сбор по расписанию — задача воркера (`/add-worker-job`).

## 3. Источник

1. Адаптер в папке источников: запрос → проверка ответа схемой (zod / pydantic) → перевод в общую модель. Поля, которых у источника нет, — явно пустые, не выдуманные.
2. Сеть: таймаут, повторы с паузой на временных ошибках (5xx, 429 с учётом `Retry-After`), понятная ошибка источника (своим классом), которая не роняет сбор по остальным источникам.
3. Регистрация в реестре; ключ и настройки — через env.
4. Для погоды — как источник участвует в «предугадывании» (вес, метрика точности) — по текущей логике сервиса; если её ещё нет — спроси.

## 4. Тесты и отчёт

Тесты на **записанных ответах** (фикстуры JSON/XML в папке тестов источника, без секретов и личных данных): нормальный ответ, пустой, ошибка, неожиданный формат (схема отклоняет). Настоящая сеть в тестах — нет. Проверка — `verifier` (TS) или `uv run pytest` и линтер Python (weather). В отчёте: условия и лимиты источника, нужные переменные окружения, что проверить вручную.
