description: План коммитов — проверка изменений на секреты, разбиение на логичные коммиты и сообщения к ним (сам не коммитит)
allowed-tools: Bash(git status *), Bash(git diff *), Bash(git log *), Bash(git ls-files *)
---

Подготовь план коммитов для текущих изменений. **Сам не коммить и не меняй индекс** — пользователь коммитит сам; если он попросит сделать коммиты — тогда да.

1. **Изменения**: `git status --short`, `git diff --stat` и `git diff --cached --stat`; при необходимости — сами правки (`git diff -- <файл>`), чтобы понять смысл.
2. **Секреты и мусор** — до всего остального. В индексе и среди новых файлов не должно быть `.env*`, `*.pem`, `*.key`, `*.secrets`, `.claude/settings.local.json`, токенов и паролей в тексте правок (`git diff | grep -iE "token|secret|password|api[_-]?key"` — проверь найденное глазами), сборки и генерации (`build/`, `.svelte-kit/`, `src/generated/`), логов. Нашлось — предупреди первым пунктом и скажи, как убрать из индекса.
3. **Разбиение**: группы по смыслу (одна задача — один коммит: функция, исправление, тесты к ней, правила). Если всё про одно — один коммит. Файлы, где смешаны правки разных задач, — назови; разделить их по фрагментам можно `git add -p` в обычном терминале.
4. **Сообщения** — по-английски, коротко, в стиле истории проекта (`git log --oneline -10`): что изменилось, без точки в конце.
5. **Ответ**: для каждого коммита — строка для пользователя вида `! git add <файлы> && git commit -m "…"`, в порядке, в котором их делать. Перед коммитом напомни о проверках (`verifier`), если код менялся после последней проверки. $ARGUMENTS
