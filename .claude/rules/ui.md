# Правила верстки и стилей (Mini App: SvelteKit + Svelte 5 + Tailwind CSS v4)

- Стилизуй разметку только utility-классами Tailwind CSS.
- Не пиши inline-стили через атрибут `style=""` и директиву `style:`, даже для мелких правок. Блоки `<style>` в `.svelte`-компонентах не используй.
- Если нужного значения нет в стандартной шкале Tailwind, используй arbitrary values (`w-[372px]`, `bg-[#1e1e1e]`) или добавь токен в `@theme` в главном CSS-файле (`src/app.css`). `tailwind.config.*` в Tailwind v4 не используется.
- Повторяющиеся наборы классов выноси в Svelte-компонент; `@apply` используй только когда вынести в компонент нельзя.
- В `.css` файлах не пиши произвольные стили, которые дублируют возможности Tailwind; там место для `@import "tailwindcss"`, `@theme`, `@custom-variant` и редких исключений.
- Исключение: значения, вычисляемые в рантайме (позиции, размеры, прогресс), задавай через CSS-переменную: `style:--progress="{value}%"` + класс `w-[var(--progress)]`.
- Не собирай классы конкатенацией строк (`bg-${color}-500`); Tailwind их не увидит. Используй полные имена классов в маппинге. Условные классы — через массив/объект в `class={[...]}` (Svelte 5).
- Цвета берутся из темы Telegram: переменные `--tg-theme-*` (`bg-color`, `text-color`, `hint-color`, `button-color`, `button-text-color`, `secondary-bg-color` и др.) подключаются как токены в `@theme`, и в разметке используются эти токены (`bg-tg-bg`, `text-tg-text`), а не захардкоженные цвета. Так интерфейс сам следует светлой/тёмной теме пользователя.
- Учитывай безопасные зоны: отступы от `--tg-safe-area-inset-*` и `--tg-content-safe-area-inset-*` для полноэкранного режима.
- Вёрстка mobile-first: Mini App открывается в основном на телефонах, ширина от ~320px, без горизонтального скролла.
- Код без разметки и стилей (логика, запросы, утилиты, серверные эндпоинты) эти правила не затрагивают.
