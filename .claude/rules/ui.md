# Правила верстки и стилей (Mini App: SvelteKit + Svelte 5 + Tailwind CSS v4)

Стили, классы и дизайн-токены. Где лежат компоненты, их props, базовые компоненты и `mergeClasses()` — `components.md`.

## Общее

- Стилизуй разметку только utility-классами Tailwind CSS.
- Не пиши inline-стили через атрибут `style=""` и директиву `style:`, даже для мелких правок. Блоки `<style>` в `.svelte`-компонентах не используй.
- Исключение: значения, вычисляемые в рантайме (позиции, размеры, прогресс), задавай через CSS-переменную: `style:--progress="{value}%"` + класс `w-(--progress)` (короткая запись Tailwind v4 для `w-[var(--progress)]`; её же предлагает подсказка VS Code).
- Повторяющиеся наборы классов выноси в Svelte-компонент (как выбрать между компонентом, `@utility` и классами на месте — `components.md`); `@apply` используй только когда вынести в компонент нельзя.
- Длинные списки классов. Если `class="…"` не помещается в строку шириной 100 символов (как у форматтера), запиши его массивом Svelte 5 `class={[…]}`, по одной смысловой группе на строку, в таком порядке: 1) положение и раскладка (`fixed`, `sticky`, `top-*`, `z-*`, `flex`, `items-*`, `gap-*`); 2) размеры, отступы, форма и текст (`size-*`, `w-*`, `p-*`, `m-*`, `rounded-*`, `text-lg`, `font-*`); 3) цвета и эффекты (`bg-*`, `text-tg-*`, `shadow-*`, `ring-*`, `outline-*`, `placeholder:*`); 4) состояния и анимация (`transition`, `hover:*`, `active:*`, `focus:*`, `disabled:*`). Неочевидную группу поясни комментарием над строкой. Короткие списки остаются одной строкой. Если и массив разрастается — элемент пора выносить в компонент.
- В `.css` файлах не пиши произвольные стили, которые дублируют возможности Tailwind; там место для `@import`, `@theme`, `:root` с базовыми значениями, `@utility` (всё — только в `app.css`), `@custom-variant` и редких исключений. `tailwind.config.*` в Tailwind v4 не используется.
- Не собирай классы конкатенацией строк (`bg-${color}-500`); Tailwind их не увидит. Используй полные имена классов в маппинге. Условные классы — через массив/объект в `class={[...]}` (Svelte 5).
- Учитывай безопасные зоны: отступы от `--tg-safe-area-inset-*` и `--tg-content-safe-area-inset-*` для полноэкранного режима (токены `page-*`, `safe-*`).
- Вёрстка mobile-first: Mini App открывается в основном на телефонах, ширина от ~320px, без горизонтального скролла.
- Код без разметки и стилей (логика, запросы, утилиты, серверные эндпоинты) эти правила не затрагивают.

## Дизайн-токены (`src/app.css`)

Все значения оформления — цвета, отступы, размеры — переменные, а не литералы.

- Все переменные живут в `src/app.css`, сразу после `@import 'tailwindcss'` (он — только здесь, один раз). В других CSS-файлах и компонентах их не объявлять: значения из `:root` доступны везде, токены `@theme` — через утилиты Tailwind. Другому CSS-файлу, которому нужна тема Tailwind (`@apply`), — `@reference` на `app.css`, а не повторный `@import 'tailwindcss'`.

`app.css` устроен в два слоя, и DRY действует внутри него тоже:

1. **Базовые значения в `:root`** — единственное место с литералами, каждый литерал ровно один раз. Палитра `--palette-*` (`--palette-white`, `--palette-blue`…), размеры `--size-*` (`--size-none: 0px`, `--size-page-gutter: 1rem`…). Утилит Tailwind не порождают, в разметке не используются.
2. **Токены по ролям в `@theme inline`** — то, что используется в разметке: цвета `--color-*` (`--color-surface` → `bg-surface`, `--color-elevation` → `shadow-elevation`), отступы `--spacing-*` (`--spacing-page-t` → `pt-page-t`). Ссылаются на `--tg-theme-*`, `--tg-*-safe-area-inset-*` и базовые значения; литералов не содержат. Оттенки и прозрачность — через `color-mix()` от палитры, производные размеры — через `calc()` от `--size-*`.

Правила использования:

- Имена — по роли, а не по значению: `--color-elevation`, а не `--color-black-20`; `--size-page-gutter`, а не `--size-16`.
- Цвет в разметке — только через токен роли. Никаких hex/rgb и палитры Tailwind (`bg-white`, `text-red-500`, `shadow-black/20`). Прозрачность от токена (`bg-tg-hint/30`) допустима.
- Поверхности — как в настройках Telegram и iOS: фон страницы — `page` (второй цвет темы) со свечением сверху, утилита `bg-page-glow` — только на `<body>` (`app.html`); всё, что лежит на странице (карточка, поле, кнопка, плашка), — `bg-surface`. Поле ввода или переключатель внутри поверхности (`Panel`) — `bg-field`: «утопленный» оттенок, иначе он слился бы с `bg-surface`. Цвета темы `bg-tg-bg` и `bg-tg-secondary-bg` в компонентах не используются: фон задаёт роль, а не конкретный цвет темы. Шапки и обёртки экрана своего фона не имеют — под ними видно свечение.
- Размеры свечения (`--size-glow*`) — от ширины окна (`vw`), а не высоты: высоту окна меняет экранная клавиатура, и фон менялся бы при каждом её открытии.
- Элемент, который мешает при вводе (плавающая кнопка над клавиатурой), прячется вариантом `typing:` (`@custom-variant` в `app.css`: в поле ввода фокус, на телефоне — открыта клавиатура): `typing:pointer-events-none typing:opacity-0`, как у `FloatingButton`. Элемент в потоке экрана, чьё место лучше отдать полям, — `typing:hidden`, как у `ActionBar`.
- Цвета берутся из темы Telegram (`--tg-theme-*`), палитра — только запасное значение для обычного браузера. Так интерфейс сам следует светлой/тёмной теме пользователя.
- Отступы, размеры, скругления внутри компонентов — стандартная шкала Tailwind (`p-4`, `gap-2`, `rounded-2xl`): она сама построена на переменной `--spacing`. Значения, которые несут смысл для всего приложения (поля страницы, безопасные зоны), — свои токены `--spacing-*`.
- Arbitrary values (`min-h-[40dvh]`) — только для разового значения. Как только то же значение нужно второй раз — заводи токен.
- Нужного значения нет — сначала добавь базовое значение в `:root` (если такого литерала ещё нет) и токен роли в `@theme`, потом используй токен.
