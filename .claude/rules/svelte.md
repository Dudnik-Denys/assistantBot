# Svelte 5 и SvelteKit

Следуй официальной документации: https://svelte.dev/docs/svelte и https://svelte.dev/docs/kit. Если правило здесь расходится с документацией актуальной версии — верна документация, а правило нужно обновить. Компоненты — в `components.md`, вёрстка и стили — в `ui.md`, серверная часть (эндпоинты, хуки, ошибки → HTTP, env) — в `api.md`, общие принципы кода — в `code.md`.

## Руны обязательны

Режим рун включён для всего проекта (`runes: true` в `apps/web/vite.config.ts`). Реактивность — только через руны, где это возможно:

- `$props()` для свойств компонента, с типом `Props` (`components.md`): `let { note }: Props = $props()`. Не `export let`.
- `$state()` для изменяемого состояния. Обычный `let` — только для того, что не должно вызывать перерисовку.
- `$derived()` / `$derived.by()` для всего, что вычисляется из другого состояния. Не `$:` и не `$effect`, который присваивает значение в `$state`.
- `$effect()` — только для побочных эффектов, связывающих компонент с внешним миром (запросы, подписки, API Telegram, таймеры). Если эффект что-то создаёт — возвращай функцию очистки. Первым делом спроси себя, нельзя ли обойтись `$derived` или обработчиком события.
- `$bindable()` — только для свойств, которые компонент действительно меняет для родителя (`bind:value`).
- Общее реактивное состояние для нескольких компонентов — в модуле `.svelte.ts` с рунами, а не в `svelte/store`. Stores — только для совместимости с библиотеками, которые их требуют.
- Повторяющаяся реактивная логика (состояние + `$effect`: поиск с задержкой, загрузка, таймеры) выносится из компонентов в `src/lib/reactive/<имя>.svelte.ts` — класс, который сам владеет полями `$state`/`$derived` и эффектом в конструкторе (пример — `DebouncedSearch`). Компонент создаёт экземпляр в `<script>` (эффект привязан к жизни компонента) и читает поля: `bind:value={search.query}`, `search.items`. Передавать в обычную функцию переменные компонента «для изменения» нельзя — она получит копии. Простые функции без состояния — в `src/lib/utils/` (см. «Где лежит код в `src/lib`»).

Устаревший синтаксис Svelte 4 не используется:

| Нельзя | Нужно |
|---|---|
| `export let x` | `let { x } = $props()` |
| `$: y = x * 2` | `const y = $derived(x * 2)` |
| `$: { … }` с побочным эффектом | `$effect(() => { … })` |
| `on:click={…}` | `onclick={…}` |
| `<slot />`, `slot="name"` | `children` / snippets: `{@render children()}`, `{#snippet name()}` |
| `createEventDispatcher` | callback-свойства: `let { onsave } = $props()` |
| `$app/stores` (`$page`) | `$app/state` (`page`) |

## Где лежит код в `src/lib`

| Папка / файл | Что там |
|---|---|
| `utils/` | Чистые функции общего назначения: без состояния, без рун, без зависимостей от Svelte, SvelteKit, Telegram и нашего API. Один файл на тему (`linkify.ts`, `dates.ts`, `classes.ts`). Тесты — не здесь, а в `tests/unit/<модуль>/` (см. `tests.md`) |
| `schemas/` | zod-схемы, нужные только Mini App (клиенту или серверу web): `api-error.ts` — тело ошибки нашего API; общие с ботом — в `packages/core/src/schemas/` (`code.md`, «Схемы zod») |
| `constants/` | Только значения, без логики: справочники, списки и таблицы соответствий, объявленные один раз (`http-status.ts` — `HttpStatus`, `sections.ts` — пункты меню, `delays.ts` — паузы поиска и автосохранения, `gestures.ts` — пороги жестов, `telegram.ts` — версии и ключи Telegram, `test-ids.ts` — `TestId` для `data-testid` (появится вместе с e2e, правила — `e2e.md`), `error-statuses.server.ts` — ошибка → HTTP-код). Допустимы короткие функции-значения внутри таблицы (как `message` в `ERROR_STATUSES`), но не алгоритмы. Объекты `as const`, а не `enum`. Файл, нужный только серверу, — `*.server.ts` (`error-statuses.server.ts`; почему — `api.md`). Константы предметной области, нужные и серверу, и боту (лимиты), — в `packages/core/src/constants/` |
| `reactive/` | Классы с рунами (`.svelte.ts`) — состояние и эффекты, которые живут вместе с компонентом |
| `types/` | Типы, общие для нескольких модулей Mini App и не выводимые из схем: общие части props компонентов (`props.ts` — `ClassProp`). Тип одного компонента — в нём самом (`interface Props`), DTO — в `packages/core` |
| `http/`, `api.ts` | Запросы к API Mini App (`api.md`, «Клиент API») |
| `server/` | Только серверный код (`api.md`) |
| `components/` | Компоненты (`components.md`) |
| корень `lib/` | Модули, привязанные к приложению: `telegram.ts`, `errors.ts` (знает ошибки `http/`), `keyboard.ts` (экранная клавиатура: закрытие свайпом вниз и удержание открытой при переходе на экран с полем ввода — работает с DOM напрямую) |

- Числа и строки со смыслом (HTTP-коды, ключи, повторяющиеся значения) не пишутся в коде напрямую — имя в `constants/`: `HttpStatus.NotFound`, а не `404`.
- Файлы `constants/` делятся по охвату, как в `packages/core/src/constants/`: общее для всего приложения — файл по теме (`http-status.ts`, `auth.ts`, `sections.ts`); нужное только одному разделу — `constants/<раздел>.ts` (`constants/counters.ts`), его импортирует только этот раздел. Константа раздела понадобилась второму — переезжает в файл по теме. Константы модулей `lib/` (`.ts`, `.svelte.ts`: пороги, задержки, версии, регулярные выражения) — тоже в `constants/`, даже если нужны одному модулю: `constants/<тема>.ts` (`gestures.ts`, `delays.ts`, `telegram.ts`, `links.ts`); подходящей темы нет — новый файл, а не константа внутри модуля. Исключение — компоненты: константа одного компонента, которую больше никто не использует, остаётся в самом компоненте (`components.md`).
- В `utils/` не кладут «всё, что не нашло места»: если функции нужно состояние, запрос, Telegram или знание о наших данных — её место в другой папке из таблицы.
- Не заводи `utils/helpers.ts`, `utils/index.ts` и подобные сборники: имя файла называет тему.
- Логика предметной области, нужная и боту, — не в `utils/`, а в `packages/core`.

## SvelteKit

- Файлы маршрутов по ролям: `+page.svelte` — страница, `+layout.svelte` — обёртка, `+page.ts` / `+layout.ts` — `load` и настройки маршрута (`ssr`, `csr`, `prerender`), `+server.ts` — API-эндпоинт. Настройки маршрута экспортируются только из `+page.ts` / `+layout.ts`.
- Приложение — SPA: `ssr = false` в корневом `+layout.ts` (данные требуют `initData`, которые есть только в браузере). Не включай SSR для отдельных страниц без причины.
- Серверный код (`lib/server/`, `hooks.server.ts`, `+server.ts`, `*.server.ts`), эндпоинты, перевод ошибок в HTTP и переменные окружения — `api.md`. Клиентский код серверный не импортирует.
- Навигация «назад» на экране — только компонент `ui/buttons/BackButton` (`<BackButton onback={…} />`): он подключает системную кнопку Telegram и показывает ссылку в обычном браузере. `useBackButton` напрямую в страницах не вызывать.
- Навигация — `goto` и обычные `<a href>`; данные, нужные до отрисовки страницы, — через `load`, а не `$effect` в компоненте, когда это возможно.
- Адреса внутренних страниц — только через `resolve()` из `$app/paths`, никаких строк-адресов: `href={resolve('/notes/new')}`, `goto(resolve('/notes'))`, с параметрами — `resolve('/notes/[id]', { id })`. Первый аргумент — идентификатор маршрута (путь папки в `routes/`), поэтому опечатка, несуществующий маршрут или забытый параметр — ошибка `bun run check`, а base path подставляется автоматически. Касается и данных (`href` в `lib/constants/sections.ts`). Внешние ссылки (`https://…`) — без `resolve`. Автоматической проверки нет (ESLint не используем) — следить на ревью и в `/verify-ui`.
- Импорты из `src/lib` — через алиас `#lib/…` с явным расширением файла.
