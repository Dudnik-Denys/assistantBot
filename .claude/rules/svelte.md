# Svelte 5 и SvelteKit

Следуй официальной документации: https://svelte.dev/docs/svelte и https://svelte.dev/docs/kit. Если правило здесь расходится с документацией актуальной версии — верна документация, а правило нужно обновить. Вёрстка и стили — в `ui.md`, общие принципы кода — в `code.md`.

## Руны обязательны

Режим рун включён для всего проекта (`runes: true` в `apps/web/vite.config.ts`). Реактивность — только через руны, где это возможно:

- `$props()` для свойств компонента, с типом: `let { note }: { note: NoteDto } = $props()`. Не `export let`.
- `$state()` для изменяемого состояния. Обычный `let` — только для того, что не должно вызывать перерисовку.
- `$derived()` / `$derived.by()` для всего, что вычисляется из другого состояния. Не `$:` и не `$effect`, который присваивает значение в `$state`.
- `$effect()` — только для побочных эффектов, связывающих компонент с внешним миром (запросы, подписки, API Telegram, таймеры). Если эффект что-то создаёт — возвращай функцию очистки. Первым делом спроси себя, нельзя ли обойтись `$derived` или обработчиком события.
- `$bindable()` — только для свойств, которые компонент действительно меняет для родителя (`bind:value`).
- Общее реактивное состояние для нескольких компонентов — в модуле `.svelte.ts` с рунами, а не в `svelte/store`. Stores — только для совместимости с библиотеками, которые их требуют.
- Повторяющаяся реактивная логика (состояние + `$effect`: поиск с задержкой, загрузка, таймеры) выносится из компонентов в `src/lib/reactive/<имя>.svelte.ts` — класс, который сам владеет полями `$state`/`$derived` и эффектом в конструкторе (пример — `DebouncedSearch`). Компонент создаёт экземпляр в `<script>` (эффект привязан к жизни компонента) и читает поля: `bind:value={search.query}`, `search.items`. Передавать в обычную функцию переменные компонента «для изменения» нельзя — она получит копии. Простые функции без состояния — в `src/lib/utils/` (см. «Где лежит код в `src/lib`»).

Устаревший синтаксис Svelte 4 не используется:

| Нельзя | Нужно |
|---|---|
| `export let x` | `let { x } = $props()` |
| `$: y = x * 2` | `const y = $derived(x * 2)` |
| `$: { … }` с побочным эффектом | `$effect(() => { … })` |
| `on:click={…}` | `onclick={…}` |
| `<slot />`, `slot="name"` | `children` / snippets: `{@render children()}`, `{#snippet name()}` |
| `createEventDispatcher` | callback-свойства: `let { onsave } = $props()` |
| `$app/stores` (`$page`) | `$app/state` (`page`) |

## Компоненты

- В `<script lang="ts">` — только состояние компонента и связка с разметкой. Алгоритмы, запросы, форматирование, работа с Telegram — в модулях `src/lib/` (их можно тестировать и переиспользовать; куда именно — в разделе ниже).
- Внутри `.svelte` TypeScript только «типовой»: аннотации и типы. Конструкции, порождающие код (`enum`, parameter properties), — в `.ts`-файлах.
- Ключи в `{#each}` обязательны для списков, которые меняются: `{#each notes as note (note.id)}`.

## Где лежит код в `src/lib`

| Папка / файл | Что там |
|---|---|
| `utils/` | Чистые функции общего назначения: без состояния, без рун, без зависимостей от Svelte, SvelteKit, Telegram и нашего API. Один файл на тему (`linkify.ts`, `dates.ts`, `classes.ts`). Тестов здесь нет: место и подход к тестам web будут определены отдельно |
| `constants/` | Только значения, без логики: справочники и списки, объявленные один раз (`http-status.ts` — `HttpStatus`, `sections.ts` — пункты меню). Объекты `as const`, а не `enum`. Константы предметной области, нужные и серверу, и боту (лимиты), — в `packages/core` |
| `reactive/` | Классы с рунами (`.svelte.ts`) — состояние и эффекты, которые живут вместе с компонентом |
| `http/`, `api.ts` | Запросы к API Mini App |
| `server/` | Только серверный код |
| `components/` | Компоненты (структура — в `ui.md`) |
| корень `lib/` | Модули, привязанные к приложению: `telegram.ts`, `errors.ts` (знает ошибки `http/`) |

- Числа и строки со смыслом (HTTP-коды, ключи, повторяющиеся значения) не пишутся в коде напрямую — имя в `constants/`: `HttpStatus.NotFound`, а не `404`.
- В `utils/` не кладут «всё, что не нашло места»: если функции нужно состояние, запрос, Telegram или знание о наших данных — её место в другой папке из таблицы.
- Не заводи `utils/helpers.ts`, `utils/index.ts` и подобные сборники: имя файла называет тему.
- Логика предметной области, нужная и боту, — не в `utils/`, а в `packages/core`.

## SvelteKit

- Файлы маршрутов по ролям: `+page.svelte` — страница, `+layout.svelte` — обёртка, `+page.ts` / `+layout.ts` — `load` и настройки маршрута (`ssr`, `csr`, `prerender`), `+server.ts` — API-эндпоинт. Настройки маршрута экспортируются только из `+page.ts` / `+layout.ts`.
- Приложение — SPA: `ssr = false` в корневом `+layout.ts` (данные требуют `initData`, которые есть только в браузере). Не включай SSR для отдельных страниц без причины.
- Серверный код — только в `src/lib/server/`, `hooks.server.ts` и `+server.ts`. Клиентский код его не импортирует (SvelteKit запрещает импорт `lib/server` на клиенте — не обходи это).
- Эндпоинты `+server.ts` тонкие: `requireUser`, вызов сервиса из `packages/core`, `Response.json(...)`, всё обёрнуто в `handleApi`. Хелпер `json` из `@sveltejs/kit` устарел (`@deprecated`) — не использовать.
- Переменные окружения объявляются в `src/env.ts` (`defineEnvVars`, в `schema` — zod-схемы; общие `optionalEnv` и `TelegramIdSchema` — из `@tgab/core/env`) и импортируются из `$app/env/private`; секреты — никогда в клиентский код.
- Навигация «назад» на экране — только компонент `ui/BackButton` (`<BackButton onback={…} />`): он подключает системную кнопку Telegram и показывает ссылку в обычном браузере. `useBackButton` напрямую в страницах не вызывать.
- Навигация — `goto` и обычные `<a href>`; данные, нужные до отрисовки страницы, — через `load`, а не `$effect` в компоненте, когда это возможно.
- Адреса внутренних страниц — только через `resolve()` из `$app/paths`, никаких строк-адресов: `href={resolve('/notes/new')}`, `goto(resolve('/notes'))`, с параметрами — `resolve('/notes/[id]', { id })`. Первый аргумент — идентификатор маршрута (путь папки в `routes/`), поэтому опечатка, несуществующий маршрут или забытый параметр — ошибка `bun run check`, а base path подставляется автоматически. Касается и данных (`href` в `lib/constants/sections.ts`). Внешние ссылки (`https://…`) — без `resolve`. Автоматической проверки нет (ESLint не используем) — следить на ревью и в `/test-ui`.
- Импорты из `src/lib` — через алиас `#lib/…` с явным расширением файла.
